# Windows-specific surface inventory

Read-only audit of how much of the workspace depends on Windows, done for the
macOS feasibility study (HEAD `5df121f`, 2026-10-13). The probes ran on an
`aarch64-apple-darwin` host (macOS 27.0, `rustc 1.99.0-nightly`); the raw probe
logs (`A-probes.log`, `A-loader.log`) live in the local research archive (see
[README.md](README.md), "Evidence archive").

Classification: **P** = portable as-is · **S** = small cfg/shim · **W** = Windows-only, needs a separate macOS implementation.

Note on `extern "system"`: on non-Windows targets it uses the platform C ABI (== SysV on macOS), so ABI/plugin/service `extern "system" fn` items are **P** — they compile and link on macOS. Only *semantics* tied to Win32 (thunks, hooks) are W.

---

## 1. Loader (`crates/parsec-orbit-loader`) — W as a mechanism, S in parts

- `src/lib.rs:1-22` — whole-crate premise: "`bcrypt.dll` proxy … Windows resolves static imports during process initialisation". **W** (no DLL-search-order proxy on macOS; counterpart = `DYLD_INSERT_LIBRARIES` dylib or static patch).
- `src/lib.rs:71` `OsStr::new(text).encode_wide()` via `std::os::windows::ffi::OsStrExt` (`lib.rs:31`); same pattern `log.rs:8,37,173`, `plugin.rs:8,53`, `webview.rs:8,18`. Probe: 4× E0433 + 5× E0599, `cargo check -p parsec-orbit-loader` FAIL. **S** (replace with `CString`/UTF-8; macOS dylib paths are UTF-8).
- `src/lib.rs:77-83` `real_bcrypt()`: `std::env::var("SystemRoot")` → `"{root}\\System32\\bcrypt.dll"`, fallback `"C:\\Windows\\System32\\bcrypt.dll"`, `LoadLibraryExW(..., LOAD_LIBRARY_SEARCH_SYSTEM32)`. **W**.
- `src/lib.rs:137-175` `resolve_stub`: `#[unsafe(naked)]` x86_64 asm (`push rcx… sub rsp, 0x68 … jmp rax`), comment documents the `0x60` xmm-save/`r9` overlap bug. **W** (x86_64-Windows ABI; macOS arm64 needs a different stub or, better, plain `dlsym` forwarding — no thunks needed without the proxy trick).
- `src/lib.rs:243-266` `DllMain(module, reason, …)`: `reason == 1` (PROCESS_ATTACH), `DisableThreadLibraryCalls`, `CreateThread(worker)`. **W** (counterpart: `#[used] #[link_section="__DATA,__mod_init_func"]` ctor or `__attribute__((constructor))`).
- `src/lib.rs:178-216` `worker()`: gates on `CLIENT_PROCESS`, calls `webview::prepare`, `pre_resolve`, `PLUGIN_WARMUP` sleep, `plugin::scan`. Logic **P**; gating constant **S**.
- `src/exports.rs:1-14` header: "`@generated by scripts/gen-bcrypt-exports.py` … 60 named exports mirrored from `C:\Windows\System32\bcrypt.dll`"; `SLOTS: [AtomicUsize; 60]`, `NAMES`, 60× `#[unsafe(naked)] pub unsafe extern "system" fn BCrypt*` thunks (`lea rax, [rip + SLOTS + N]; jmp resolve_stub`). **W** (entire file is the proxy mechanism).
- `src/plugin.rs:65-100` `Win32Platform: Platform::load`: `LoadLibraryW` → retry `LoadLibraryExW(LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR | LOAD_LIBRARY_SEARCH_SYSTEM32)`, `GetProcAddress` for `EXPORT_QUERY/INIT/SHUTDOWN/LEGACY_INIT`, error text `"could not load {} (LoadLibraryW error {first}, LoadLibraryExW error {second})"`. **W** (counterpart: `dlopen`/`dlsym` via `libc` or raw link; error via `dlerror`). Trait shape itself is the isolation point (see §8).
- `src/log.rs` — `CreateFileW/WriteFile/CloseHandle` (`probe`, `write_line`), `OutputDebugStringW`, `GetLocalTime`/`SYSTEMTIME`, `GetModuleFileNameW` in `process_name()` (`rsplit('\\')`), comment "`%APPDATA%` is missing in service environments" (`init`). Tests assert `.exe` suffix (`process_name_is_the_bare_executable_name`) and Win32 codes 3/5. File I/O logic **S** (port to `std::fs::OpenOptions::append` + `debug_assert`/stderr mirror); `process_name` **S** (`std::env::current_exe`); `%APPDATA%/%TEMP%` fallback chain lives in `config.rs` (below).
- `src/webview.rs:8-52` `prepare(port)`: `GetEnvironmentVariableW`/`SetEnvironmentVariableW` on `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`, value `"--remote-debugging-port={port} --remote-allow-origins=*"`. Env plumbing **S** (`std::env`), but the *mechanism* is **W**: macOS WebKit has no equivalent env var — remote inspection is per-process/XPC, needs a different implementation.
- `src/config.rs:13` `CLIENT_PROCESS = "parsecd.exe"`; `from_lookup`: `PARSEC_ORBIT_PLUGIN_DIR` (`;`-separated), `loader_dir/plugins`, `%APPDATA%\ParsecOrbit\plugins`; log candidates `PARSEC_ORBIT_LOG` → `%APPDATA%\ParsecOrbit\parsec-orbit.log` → `<loader_dir>\parsec-orbit.log` → `%TEMP%\parsec-orbit.log`; `data_root = %APPDATA%\ParsecOrbit\data`; `PARSEC_ORBIT_DEVTOOLS(_PORT)` default 9222; `PARSEC_ORBIT_HOST=any`. All parsing logic **P**; the *default paths/vars* **S** (`~/Library/Application Support/ParsecOrbit`, `$TMPDIR`, `;`→`:` separator).
- `src/testutil.rs` `pe_export_names` (MZ/`PE\0\0`/PE32+ `0x20B` parsing) and `system32()` (`%SystemRoot%\System32`). **W** (test-only; macOS counterpart parses Mach-O `LC_ID_DYLIB`/`LC_LOAD_DYLIB`).
- `Cargo.toml`: `[lib] name = "bcrypt", crate-type = ["cdylib"]` + comment "The file name is the whole point"; `windows-sys 0.61` with 9 feature groups (Foundation/Security/FileSystem/Environment/IO/LibraryLoader/Debug/SystemInformation/Threading). **W** (name + dep).

## 2. Core (`crates/parsec-orbit-core`) — P, with S naming/manifest points

- `src/lib.rs:1-14` "Plugin loading logic that does not need Win32 … `Platform` maps a library … `Logger` receives the one-line decisions". **P** — the isolation boundary. `Env { platform, logger, loader_version, data_root }`, `Module { handle: usize /* HMODULE on Windows */, exports }`. **P** (`handle: usize` already opaque; dlopen handle fits).
- `src/host.rs:282-351` host callbacks `host_log/host_log_ex/host_query_interface/host_register_interface/host_unregister_interface` are `unsafe extern "system" fn`. **P** (ABI-compatible on macOS).
- `src/scan.rs:59-72` `is_dll()` — extension `.eq_ignore_ascii_case("dll")`; `first_dll()`; `src/scan.rs:225-242` loose `*.dll` discovery ("`<client dir>\plugins\loose.dll (no manifest, legacy layout)`", header `src/scan.rs:6-8` cites `<client dir>\plugins`, `%APPDATA%\ParsecOrbit\plugins`). **S** (gate extension/kind per `target_os`: `dll` vs `dylib`; keep both accepted or rename).
- `src/manifest.rs:12` `KIND_DLL = "dll"`; default kind `"dll"` (`package.rs:123` in market mirrors it). **S** (add `KIND_DYLIB`/accept both; manifests use `entry = "*.dll"` everywhere — see §7).
- `src/kind.rs`, `src/activate.rs`, `src/plan.rs` — pure logic, paths via `Path`, absolute-path leak for handlers. **P**.
- Doc strings referencing `%APPDATA%` (`lib.rs` Env, `scan.rs` header). **S** (docs only).
- Probe: `cargo check` OK; `cargo test` 80 passed / 5 failed — failures are **pre-existing, not macOS**: `host.rs:439` test static `HEADER = new(8, 1, 2)` vs `size_of::<ParsecOrbitInterfaceHeader>() == 12`, so `register()` returns `ERR_INVALID (-1)` not `OK (0)` (`a_name_can_only_be_registered_once`, `a_registered_table_is_found_with_its_owner`, `only_the_owner_can_unregister`, `plugins_register_and_find_interfaces_through_their_own_table`, `the_reserved_prefix…`). Repro single-threaded too. Needs a repo fix (test header size), independent of this study.

## 3. Plugin ABI (`crates/parsec-orbit-plugin-abi`) — P

- `src/lib.rs`: `#![no_std]`, `#[repr(C)]` `ParsecOrbitPluginDesc/Host/InterfaceHeader/PluginLoadInfo/KindHandlerV1`, `ABI_VERSION = 1`, `EXPORT_QUERY/INIT/SHUTDOWN/LEGACY_INIT`, `INTERFACE_*` names, `HOST_REVISION_1_SIZE`/`HOST_REVISION_2_SIZE` split by `target_pointer_width` (64: 96/208; 32: 52/108 — macOS arm64 uses the 64-bit row, **P**). All callbacks `extern "system"` (**P** per note above). Probe: check OK.
- `Cargo.toml` + `README.md:21`: `keywords/categories` contain `windows`, `os::windows-apis`; docs.rs `default-target/targets = x86_64-pc-windows-msvc`; "Windows only in practice (the loader is a `bcrypt.dll` proxy)". **S** (metadata only; widen targets).

## 4. Plugin SDK (`crates/parsec-orbit-plugin-sdk`) — P except runtime (W, cfg-gated correctly)

- `src/plugin.rs:146-182` `declare_plugin!`: emits `#[no_mangle] pub unsafe extern "system" fn ParsecOrbitPluginQuery/Init[/Shutdown]`. **P**.
- `src/runtime.rs:80-166` `#[cfg(windows)] mod heap`: `#[link(name = "kernel32", kind = "raw-dylib")] extern "system" { GetProcessHeap/HeapAlloc/HeapReAlloc/HeapFree }`, `ProcessHeap: GlobalAlloc` (+over-aligned path, `HEAP_ZERO_MEMORY`). Correctly cfg-gated — but there is **no non-Windows counterpart**, so `freestanding!()` fails off-Windows. Probe (via hello-nostd): E0425 "found an item that was configured out" at `runtime.rs:166`. **W** (counterpart: `malloc/free/realloc` via `#[link(name = "c")]` or `core::alloc` shim).
- `src/runtime.rs:69-78` `abort()`: `#[cfg(all(target_arch = "x86_64", windows))]` → `int 0x29, ecx=7`; else `spin_loop`. Compiles everywhere (**P** as code) but the fallback never terminates — **S** (macOS arm64 wants `__builtin_trap`/`udf`/abort).
- `src/runtime.rs:214-343` `__runtime_support!`: x86_64 MS-ABI asm (`memcpy/memmove/memset/memcmp/bcmp/strlen/__chkstk/__CxxFrameHandler3/_fltused` using rcx/rdx/r8), `_DllMainCRTStartup: mov eax,1; ret`, `#[link_section = ".drectve"] b" /NODEFAULTLIB "`. Probe: "invalid Mach-O section specifier … requires a segment and a section". **W** (needs AAPCS64 asm + `__TEXT,__text` sections + no drectve on macOS).
- Doc comment `runtime.rs:185` "Only `x86_64-pc-windows-msvc` is supported" + workspace `panic = "abort"` profiles. **S** (docs; abort profile is platform-neutral).

## 5. SDK-std (`parsec-orbit-plugin-sdk-std`) — P

No `windows-sys`, no `std::os::windows`. Probe: check OK. **P** throughout.

## 7. Manifests / naming (cross-cutting) — S

Every `plugin.toml` pins a `.dll` entry: `hooks`, `js-runtime`, `webview-bridge`, `high-bitrate-webview`, `high-bitrate-native`, `config` (`entry = "parsec_orbit_plugin_<x>.dll"`), fixtures (`parsec_orbit_fixture_plugin.dll`, `parsec_orbit_fixture_nostd.dll`), examples (`parsec_orbit_plugin_hello[_nostd].dll`); only `bandwidth-ts` uses `dist/main.js`. Tests assert these strings (`hooks` manifest test, `high-bitrate-webview lib.rs:252-256`, `high-bitrate-native lib.rs:204-208`, `config lib.rs:192`, e2e `common/mod.rs:80-90` `bcrypt.dll` + 9 `*.dll` + `callpaths.exe`/`roundtrip.exe`, `CLIENT = "parsecd.exe"` in `sdk.rs:12`/`js.rs:9`/`loader.rs:16`). **S** (per-target entry default + test expectations).

## 8. Already isolated behind `Platform`/`Logger` (what macOS reuses)

- Decision logic: `core::{scan,plan,manifest,kind,activate}` + `Env` — untouched by a macOS port.
- `Platform::load(path) -> Result<Module, String>` — macOS impl = `dlopen(path, RTLD_NOW)`, `dlsym` × 4 exports, `dlerror` text. `Logger` — macOS impl = append-only file + `os_log`/stderr.
- `sdk-std::testing::MockHost` — plugin unit tests already run without any OS loader (used by hooks/js-runtime/config tests).
- Kind-handler abstraction (`parsec-orbit.kind.<kind>`) — js plugins never touch DLL machinery; js-runtime moves over unchanged once *some* dll-kind loader exists.

## 12. Sketch: smallest path to `cargo check --workspace` on macOS (no edits made)

1. `loader`: `cfg(target_os = "windows")` on `exports`/`DllMain`/thunks; `cfg`-split `plugin.rs` (Win32Platform vs `dlopen` MacPlatform), `log.rs` (Win32 vs `std::fs` append), `webview.rs` (env-var vs macOS endpoint publish); `OsStrExt::encode_wide` → `CString`. Crate name stays `bcrypt` only on Windows.
2. `core/scan.rs` + manifests: accept `dylib` extension alongside `dll` on macOS (`is_dll` → `is_plugin_lib`); keep `KIND_DLL` wire value.
3. `sdk/runtime.rs`: `#[cfg(unix)]` malloc heap (`extern "C" { malloc/free/realloc }`), AAPCS64 `global_asm!` CRT stand-ins, `__builtin_trap` abort, drop `.drectve` off-Windows.
4. `hooks`, `high-bitrate-native`, verify tools, e2e host: `cfg(target_os = "windows")` (exclude from macOS workspace check initially; reimplement behind the same `Platform`/service traits later).
5. `config.rs` defaults: `~/Library/Application Support/ParsecOrbit`, `$TMPDIR`, `:` separator on non-Windows.
6. CI: add `macos-26` (arm64) job running the portable subset; keep `windows-latest` for the full suite incl. e2e.

## 13. M0 outcome (2026-10-13)

The sketch above is implemented through M0a/M0b/M0c, with a few differences
worth recording:

* 1 landed as `#![cfg(windows)]` on the proxy crates plus a **separate**
  `crates/parsec-orbit-loader-macos` crate, not a cfg-split inside `loader`.
  The Windows crate is untouched by the macOS build and keeps its import
  mirroring; macOS has its own `Platform`, `Logger` and config.
* 2 landed as `KIND_DYLIB` and `Platform::native_kind()`; the foreign kind is
  skipped with a log line instead of being accepted (`50c74e7`).
* 3 landed as the `freestanding!` aarch64-Mach-O flavour over libSystem
  (`020ee7f`); `fixture-nostd` and `hello-nostd` build and load on macOS.
* 4 stayed cfg-gated (no reimplementation in M0); `loader-host` compiles to a
  stub main on unix so the e2e crate still checks.
* 6 landed in `.github/workflows/test.yml`: `test-macos` on `macos-26` runs the
  JS suite, `cargo check --workspace --all-targets`, `cargo test --workspace`
  and `cargo fmt --check`; the Windows job is unchanged.

The `core` test failures in section 11 were the stale alignment fixture, fixed
in `50c74e7`. Two further portability gaps surfaced only once macOS ran the
whole workspace: the market's Windows path handling (`d3294a2`) and a
plugin-config store test that only a unix filesystem could expose (`22d6ee9`).
